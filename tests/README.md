# 補正のテスト

歌の補正（音の高さ・コード付け・リズム）を、正解つきの歌のデータで採点する。
補正の作りを変えたら、ここで前より良くなったかを数字で確かめる。

## データ

Dai, Mauch & Dixon (2015) "Analysis of Intonation Trajectories in Solo Singing" のデータを使う。
アマチュア中心の39人が、伴奏なしで3曲を3回ずつ歌った 21,762 音。1音ごとに、楽譜の高さ・長さと、実際に歌った高さ・時刻が入っている。

- 1音ごとの正解（`tsom-intonation.csv`）：公開リポジトリ `dai2015analysis-resources` の `data/` にある。
  元のサーバー（code.soundsoftware.ac.uk）につながらないときは、インターネットアーカイブの保存版から取れる。
- 録音：figshare（doi:10.6084/m9.figshare.1482221、CC BY 4.0）。今のテストでは使っていない。

`songs/testdata/dai2015/tsom-intonation.csv` に置く（`songs/` は Git の管理外）。

## 音の高さ

    node tests/eval-pitch.mjs

歌った高さ（小数）を半音に直す処理（`pitchStage`）を採点する。

- **音が合う**：直した音が、楽譜の音（歌い手のキーへ移した上で）と同じ割合
- **平均のずれ**：直した音と楽譜の音の差（半音）
- **形が合う**：隣の音への上がり下がりが、楽譜と同じ割合
- **下位10人**：音が合う割合が低い10人の平均
- **キー**：推定したキーが合っている割合（かっこ内は平行調も正解とした場合）

条件は、歌ったままのほかに、研究でわかっている崩れ方を足したもの（`docs/correction-research.md`）。
音程の幅が 0.69 倍に縮む、音ごとに 0.5 半音ばらつく、基準の高さが 2 半音流れる、の組み合わせ。
どの条件でも、録音ごとに半音未満のずれを足している（自由に歌うと、高さはピアノの音に合わないため）。

方式の設定を変えて試すときは、第1引数に JSON を渡す。

    node tests/eval-pitch.mjs '{"kMargin":0.1}' short

### 結果（2026-10-04）

「音階」つき（キーの音階に寄せる）での、音が合う割合。

| 条件 | v1（前の方式） | v2（今の方式） |
|---|---|---|
| そのまま | 70.2% | 82.7% |
| 幅が縮む | 40.1% | 72.7% |
| 縮む＋ばらつき | 37.2% | 38.9% |
| 縮む＋ばらつき＋流れ | 36.1% | 36.5% |
| ばらつきだけ | 56.2% | 58.6% |

ばらつきが大きいと、どの方式でも元の音は当てられない（歌った高さに、元の音の手がかりが残っていない）。
その場合に大事なのは、上がり下がりの形を残すことで、v2 は v1 より 4〜5 ポイント多く残す。

注意：v2 の設定のいくつか（広げるかどうかの境目など）は、このデータで結果を見ながら決めた。3曲とも西洋の長調・短調の曲なので、ほかの種類の歌でも同じ数字になるとは限らない。

### 聴き比べの結果（2026-10-05）：v2 は標準にしない

実際に自由に歌った録音（1件）で、v1 と v2 の結果を MP3 にして聴き比べてもらった。
**v2 は「元の歌からかなりかけ離れている」という判断で、不採用。** 標準は v1 に戻した。

- 上の表の数字と、「行の中の上がり下がりの形が残る割合」（82% → 95%）は v2 のほうが良かった。それでも、耳では v2 のほうが元の歌から遠かった。
- つまり、このテストの採点は、「本人の歌に聞こえるか」を測れていない。
- 考えられる原因（未確認）：v2 は行ごとに基準の高さを動かすので、行と行の高さの関係が変わる。音階の音への割り当てで、歌った高さから離れた音を選ぶことがある。この録音はキーの手がかりが弱く、音階に乗せる前提そのものが合っていない。
- 今後、方式を変えるときは、公開データの数字だけで決めず、実際の録音での聴き比べを必ず通す。

## コード付けと理論チェック

    node tests/eval-chords.mjs

楽譜どおりのメロディに付けたコードを基準にして、崩れた歌から付けたコードがどれだけ同じになるかを見る。
あわせて、「音程を整える（理論チェック）」が、合っている音をどれだけ動かしてしまうかを強さごとに出す。

### 結果（2026-10-05）

| 条件 | 基準と同じコード |
|---|---|
| そのまま | 72.4% |
| 幅が縮む | 61.3% |
| ばらつきだけ | 34.1% |
| 縮む＋ばらつき | 13.2% |

- **試して採用しなかったもの**：音符に丸める前の高さからコードを決める方式（MySong の考え方）。基準と同じコードになる割合が 72.4% → 約70% に下がった。音の高さの補正（v2）が、丸める前の高さの手がかりを既に使っているためと考えられる。
- **理論チェックは、合っている音を動かすことが多い**（歌ったままの条件。動かした音のうち、合っていた音を外した割合／外れていた音を合わせた割合）：
  弱 2.7%／0.1%、中 18.5%／0.9%、強 23.2%／1.2%。
  理論チェックの目的は「コードとぶつからないこと」で、歌った節を残すこととは別。初めの強さを「弱」に変えた。

## 拍へのあてはめ（リズム）

    node tests/eval-rhythm.mjs

音の時刻（秒）を、行の中の拍の位置に直す処理（`rhythmStage`）を採点する。
4拍子で1行が2小節の曲（Do-Re-Mi）だけを使い、行の間の休み・行ごとのテンポの変化・音ごとのゆれを足した条件でも測る。

### 結果（2026-10-05）

音の始まりの位置が、楽譜と同じ割合。

| 条件 | v1（今の標準） | v2（試した方式） |
|---|---|---|
| そのまま | 89.5% | 96% |
| 行の間の休みがばらばら | 54.6% | 92% |
| 休み＋行ごとにテンポが変わる | 56.3% | 91% |
| ＋音ごとのゆれ 0.05秒 | 55.2% | 66% |
| ＋音ごとのゆれ 0.1秒 | 54.4% | 53% |

v2 は、行ごとに「音の始まりがいちばん拍の刻みに乗るテンポ」を探す。テストでは大きく良くなる。

**それでも標準にしていない。** 実際に自由に歌った録音（1件）で確かめると、v2 では行の終わりに詰められる音が増えた（歌詞ありで 5 → 8、歌詞なしで 7 → 14）。拍の頭に乗る音の割合も増えなかった。
テストの曲はどの行も同じ長さだが、実際の歌は歌詞の文字数が行ごとに違い、行ごとに速さが変わる。テストの条件が、対象の歌に合っていない。

わかったこと：

- リズムは、公開データだけでは確かめきれない。自由に歌った録音が要る。
- 「歌詞1行を決まった小節数に入れる」という今の前提そのものが、実際の歌に合っていない可能性がある。行の長さを、歌詞の文字数や歌った時間に応じて変える作りを検討する。
